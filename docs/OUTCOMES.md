# Outcomes and reported usage

The admin **Outcomes** view uses explicit status transitions, receipts, decisions, reviews, resume records and reservation-conflict records. Every timing distribution includes a sample count. Description edits and assignment-only changes do not restart status clocks. Completion transitions and distinct completed tickets are separate; reopening is a transition out of done. Only closed intervals between observed transitions are counted. Pre-instrumentation history and unfinished intervals are not reconstructed. Project/ticket deletion removes associated history, so metrics describe retained history.

First-review acceptance counts the first *reviewed* proposal for each ticket, excluding pending proposals. Decision wait excludes cancellations. Unanswered-request age includes pending and acknowledged reply requests. Resume-to-progress uses explicit agent reports and is not a correctness assessment. `nomos resume` records a resume ID; after making progress, use `nomos --project ID progress RESUME_ID "what changed"`. Repeating the same progress does not reset its timestamp.

The legacy metrics endpoint preserves its approximation and labels it as such; `observed_completions_by_day` is the separate transition-based measure. `/outcomes` is admin-only. Experiments and usage are project-readable.

Import completed experiment manifests with `POST /api/projects/{id}/experiment-runs` or the benchmark CLI. Manifests record task/fixture/source revision, condition, trial order seed, agent count, runner/model/version (unknown allowed), context policy, evaluation configuration, timestamps, evidence references and optional acceptance/intervention counts. Manifests are immutable through this initial API; import the completed manifest once with a stable idempotency key. `GET /experiment-runs` provides bounded pages and grouped usage.

Optional usage reports go to `/experiment-runs/{run_id}/usage`: `source`, `sample_id`, `unit`, `mode`, `epoch`, `sequence`, `quantity`, and optional owned `session_id`. A sample ID is unique per run/session/source. Identical retries replay; differing retries conflict. Delta series sum their samples. Cumulative series use the maximum in an epoch; out-of-order values must still be monotonic by sequence. A reset requires a new explicit epoch. Do not mix delta/cumulative or pricing metadata in one series. Totals are grouped by source/unit/epoch, rather than combining incomparable measures.

Missing usage is `null`, not zero. `unit: "cost"` requires an ISO currency code and a reported pricing source/version. Nomos does not fetch prices or derive costs from tokens. Samples and outcome judgments are reported, not independent measurement. Experiments, usage, resumes and conflict observations are included in project exports and removed with the project.
